# 程序化世界系统：架构设计

状态：草案，待评审。本文是项目转向"统一的生成式世界系统"的设计依据；它取代
`ARCHITECTURE.md` 里那份面向单一地形/城市流水线的七层描述。

## 1. 目标与非目标

**目标。** 做一个尽可能真实、尽可能复杂的程序化世界，并且**一切**都程序化生成：从一片树叶，
到便利店货架上的一瓶饮料，再到一颗螺丝。世界本来就复杂，只有把复杂度做上去，它才真实。

它服务任何需要"世界"的系统：类 GTA 的游戏、自动驾驶与机器人仿真、可视化、训练数据生成。
这些消费者要的东西不同（画面、碰撞、地面真值、传感器模型），所以世界必须以**语义和物理**为
本体，渲染只是消费者之一。

**非目标。** 不为某个渲染器或引擎优化；不预先烘焙整个世界；不追求某一种风格。

## 2. 原则

- **P1 世界是地址的函数。** 任何位置、任何精度的内容，都是（世界种子，地址，粗层已定状态）
  的纯函数。没有"生成过程的状态"，没有"先后顺序"。
- **P2 稳定。** 同一处任何时候、任何入口求值，结果逐位相同。
- **P3 衔接。** 相邻区域各自求值，边界一致；粗层定下的东西，细层只能细化，不能推翻。
- **P4 复杂度按需付费。** 展开到多深由消费者要的精度决定；没人看的地方不存在。
- **P5 语义与物理优先。** 产出是带类别、关系、物理属性的实体；网格、纹理是下游"实现"。
- **P6 知识即数据。** 物种、产品、标准、法规、材料是数据包，不是写死的代码。加一种东西
  应当是加数据。
- **P7 契约而非实现。** 模块之间只通过小而稳定的契约通信；任何模块可以独立使用。
- **P8 可溯源、可复现、可验证。** 每个实体记得自己的来历；"真实"用统计检验对照真实数据，
  而不是靠肉眼。

## 3. 核心概念

### 3.1 地址与"塌缩"

世界按层级地址组织（四叉树或更细的空间层级 + 语义层级，如 区域 → 街区 → 建筑 → 楼层 → 房间 →
货架）。一个区域在被观察前只是一组"可能"；**塌缩**就是在给定约束下确定唯一结果：

```
state = collapse(layer, address, seed, parent_state, edge_labels)
```

它与波函数塌缩（WFC）相似：未观察时不决定，决定时满足约束，决定后不变。但**不依赖顺序**：

- 约束**自粗到细向下传播**，方向固定；
- 兄弟区域之间的共享边，其取值由**父级用哈希一次性决定**（边标签，类似 Wang 瓦片），
  所以相邻区域天然衔接，与谁先求值无关；
- 选择由哈希驱动，同样的输入永远得到同样的选择。

图层内部怎么实现由图层自己决定：连续量用细化（中点位移）、点过程（哈希格点 + 排名阈值，
放大只增不换位）；离散的规则型局部布局（沿街建筑相邻规则、立面开窗样式、货架陈列）可以用
真正的 WFC，但边界条件由边标签预先固定，种子取区域地址的哈希，所以它仍是地址的纯函数。

### 3.2 实体模型

世界的产出是**实体（Entity）**：

```
Entity {
  id:        稳定ID = hash(父ID, 图层, 局部键)
  class:     本体类别（如 plant.tree.broadleaf、road.lane、product.beverage.bottle）
  parent:    父实体
  relations: 邻接/连接/包含等关系（车道连接、货架上的位置……）
  attributes:类别相关的属性（物种、车道宽度、容量……）
  geometry:  几何"配方"（参数化形体，不是网格）
  material:  材质（见 3.5）
  physics:   物理属性（质量、摩擦、碰撞体……）
  expand(f): 在精度 f 下展开出子实体
}
```

展开是无限向下的：一个便利店可以展开为货架，货架展开为商品，商品展开为包装与标签，标签展开为
文字与油墨。每一级只在被需要时才计算。

### 3.3 图层与契约

**图层（Layer）**是一个有版本的纯函数生成器：

```
Layer {
  id, version,
  inputs:  [ (契约, 必选/可选, 精度关系) ],
  outputs: 契约,
  levels:  支持的精度/层级,
  collapse(address, seed, inputs) -> 产出,
}
```

**契约（Contract）**是小而稳定的类型/接口：`HeightField`、`WaterNetwork`、`CoverField`、
`RoadNetwork`、`LaneGraph`、`Parcels`、`Species`……图层依赖的是契约，不是别的图层的实现：

- 树图层依赖 `CoverField` 和 `HeightField`。任何实现了这两个契约的东西都能喂它：我们的地形、
  一块手绘的地、真实 DEM。想"只生成树"，给它一个常量 `CoverField` 即可。
- 行道树图层依赖 `RoadNetwork` 与 `Species`。"树和街道的逻辑相关"表达成数据依赖，而不是
  代码耦合。

规则：

- 依赖图必须无环；相互影响靠"先结构后细节"的顺序解决（先路后树，树避开路）。
- 可选依赖缺失时降级，不报错（没有道路数据，树就不避路）。
- 引擎做拓扑排序、缓存（键 = 图层 + 版本 + 地址 + 种子）、并行与按需求值。

### 3.4 参数族与目录

复杂度来自数据。**参数族（Parametric family）**= 一个生成器 + 参数分布 + 约束：

- 螺丝：ISO 标准的螺纹/头型/长度系列，加材质与表面处理；
- 饮料瓶：包装规格（容量、瓶型、盖型）+ 标签生成器（版式、配色、文字）+ 合成的品牌；
- 树：物种目录（树形文法、叶形、树皮、物候、生境），由气候与地形选择。

**目录（Catalogue）**是数据包，带版本与来源（标准号、公开数据集、许可）。新增一个物种或一种
螺丝是新增数据；引擎不变。

### 3.5 材质与物理

材质是物理量，不是 RGB：多波段反射率（可见光/近红外）、粗糙度、折射率、摩擦系数、湿润状态
响应、介电常数（雷达）……同一份定义同时服务渲染、激光雷达/雷达仿真和轮胎摩擦。

### 3.6 精度（Fidelity）

精度是**查询参数**，由消费者决定：自动驾驶仿真要车道级几何与路面反射率；游戏在玩家走进店里时
才要货架上的商品；可视化要远景的树冠分布。同一世界，不同消费者看到不同深度，但在共同的深度上
看到的是同一个东西。

### 3.7 消费者与导出

核心库只提供查询：

```
world.query(region, fidelity, layers, filter) -> 实体流
```

渲染器、物理引擎、AV 仿真器、游戏、训练管线都是**消费者**。导出器把实体转成目标格式：
glTF/USD（网格与场景）、OpenDRIVE/Lanelet2（车道与交规）、3D Tiles（流式）、实例列表、
语义分割真值。实现器（realizer）把配方变成网格、纹理、碰撞体，位于核心之外。

### 3.8 溯源、版本、复现

每个实体记录（图层@版本，种子，地址）。世界的身份是（世界种子，图层集合及版本）。图层的行为
一变就升版本；用快照测试保证"同一身份得到同一世界"。

### 3.9 验证

- 确定性测试：同一位置从不同入口求值逐位相同。
- 衔接测试：相邻区域的共享边一致。
- 统计真实性检验：树高分布、冠幅/胸径关系、道路曲率分布、农田地块面积分布、建筑层数分布等，
  对照真实数据（许可明确的数据源）做分布检验。
- 性质测试：不变量（车道图连通、建筑不压路、螺纹符合标准公差）。

### 3.10 多样性：每个地方都不一样

程序化的意义在于世界没有重复。两处地方只要条件不同，形态就应该不同；条件相同，也应该是同一类
但不同的个体。做法：

- **参数场**：文化/地区、年代、财富、密度、地形、气候、产业……是随位置连续变化的场（本身也是
  图层的产出）。每个位置的路网形态、建筑类型、材料、植被，都是这些场在该点取值的函数。
- **生长历史**：聚落不是一次生成的。核心是最早的、形态不规则；后来的片区按当时的规划方式生长
  （规整网格、沿路延展、环线、新区），受河流、地形、既有道路约束。同一城市不同街区年代不同。
- **组合式文法**：建筑不从有限样式里挑，而是体量、立面分格、构件、材料、色彩、老化、改造痕迹
  各自独立由参数决定，再由实体自己的 ID 哈希取值；同一类建筑的每一栋都是不同个体。
- **禁止拼贴**：任何"有限几块东西平铺/重复"的做法（有限个纹理瓦片、有限个预制建筑）都视为
  缺陷，除非它是明确的低精度占位。

## 4. 打包与依赖

```
worldgen-core        地址、种子、哈希、边标签、几何基础类型、Layer trait、引擎（缓存/调度）
worldgen-contracts   契约类型与接口（HeightField、CoverField、RoadNetwork、LaneGraph……）
worldgen-ontology    本体：类别、关系、属性模式
worldgen-materials   材质与物理模型
catalogues/*         数据包：species、products、standards、codes（带版本与来源）
layers/*             各生成图层，每个一个 crate；只依赖 core + contracts + 它用到的目录
realizers/*          实现器：配方 → 网格/纹理/碰撞体
exporters/*          glTF/USD/OpenDRIVE/3D Tiles……
hosts/*              宿主：桌面（Tauri）、WASM、服务（gRPC/HTTP）
```

依赖方向：`layers → contracts/core`；`realizers → ontology/materials`；`hosts → 以上全部`。
**图层之间不直接依赖**，只通过契约。核心不知道渲染器、Tauri、浏览器。

## 5. 现有代码的映射与迁移

| 现有 | 归宿 |
| --- | --- |
| `terrain-core`（高程、气候、地质） | `layers/terrain`、`layers/climate`；`fluvial` → `layers/erosion` |
| `terrain-core` 水系 | `layers/hydrology`（产出 `WaterNetwork`） |
| `infrastructure`（选址、路网、农田） | `layers/settlement`、`layers/roads`、`layers/landcover` 三者拆开 |
| `urban`（街网、地块、建筑规划） | `layers/streets`、`layers/parcels`、`layers/buildings` |
| `city-scene` 树 | `layers/trees` + `catalogues/species` + `realizers/tree` |
| `city-scene` 建筑/街道/设施网格 | `realizers/*` |
| `city-scene` 车流/信号 | 仿真消费者，读 `LaneGraph`/`Signals` 契约 |
| `Terrain3D.tsx` | 拆成 TS 侧的调度器 + 每类实体一个渲染插件 |

采用**绞杀式迁移**，应用始终可运行：

1. 建 `core` 与 `contracts`，附带确定性与衔接测试。
2. 现有地形以适配器形式提供 `HeightField`/`WaterNetwork`，算法不动。
3. **先做道路（S1）再做建筑（S2）**：重写为层级的、按地址求值的新实现；旧的 `urban`/
   `infrastructure` 在新实现达到同等能力前保留，作为对照与回退。同时消除重复定义（道路等级、
   路口半径）与河流不一致。
4. 树（S4）独立成图层，行道树依赖新的道路契约。
5. 新写的农田、森林直接建在新核心上，不再走像素烘焙。

## 6. 垂直切片（用来检验架构，不是附属品）

每条切片都从粗到细穿过所有层次；"过关"即对应的统计与不变量测试通过，而不是画面好看。
**先做道路和建筑**：它们层级最深、约束最多、最复杂，最能暴露架构的问题。

- **S1 道路（含自动驾驶语义）**：区域路网 → 聚落的主干骨架 → 街区细分出的街网（等级逐级降低）
  → 车道图、转向与优先权 → 路口几何（缘石半径、渠化）→ 标线、标志、信号相位 → 路面材质
  （摩擦、反射率）；与 OpenDRIVE/Lanelet2 互导。
  验收：层级路网是地址的纯函数（不同入口求值相同）；相邻区域衔接；车道图连通；路段与路口尺寸
  符合设计规范；道路等级、曲率、路口间距、街区面积的分布与真实城市的统计相符；不同位置的
  形态可区分（不是同一模板）。
- **S2 建筑（街区 → 室内）**：地块（沿街面、进深、形状）→ 土地用途与类型（按参数场）→ 体量与
  退台 → 结构与层高 → 立面分格与构件 → 开窗、阳台、空调机位、雨棚、招牌 → 屋顶与设备 → 楼层
  平面 → 房间。
  验收：每栋建筑是自身 ID 的纯函数；同一街区建筑彼此不同但属同一类；层数/层高/面宽/退线符合
  规范；统计分布与真实城市相符；展开到更深精度时上一层的形体不变。
- **S3 便利店（街区 → 油墨）与标准件**：沿街底商 → 店铺平面 → 货架 → 商品 → 包装 → 标签 →
  文字与油墨；螺丝等标准件的参数族。验证"目录即数据"和无限向下展开。
- **S4 树（叶 → 林）**：叶形与叶脉 → 枝条 → 单树 → 林分 → 区域森林分布。只依赖 `CoverField`/
  `HeightField`，可独立使用；行道树依赖 S1 的 `RoadNetwork`。

## 7. 风险与对策

- **范围过大**：只通过垂直切片推进；每个切片完成才扩展，禁止"水平铺开所有层"。
- **复杂度失控**：本体 + 契约 + 版本 + 测试；图层之间禁止直接依赖。
- **性能**：Rust 核心、并行、按地址缓存；精度按需；避免把中间产物序列化成 JSON。
- **数据来源与许可**：目录必须记录来源与许可；优先标准文档与许可明确的开放数据。
- **真实性无法靠感觉判断**：统计检验作为验收，视觉评审作为补充。

## 9. 已实现：S1 道路层（`worldgen-core` / `worldgen-contracts` / `worldgen-roads`）

现状与上面的设计一致，下面是落地时做的具体选择。

**核心（`worldgen-core`，仅标准库）**：地址 `Cell{level,x,y}`、由哈希派生的种子（无有序随机流）、
边标签、有版本的图层与引擎（缓存键 = 图层 + 版本 + 地址；注册时检查重名、缺依赖、环；运行时拒绝读取
未声明的输入）、哈希晶格噪声。测试：任意求值顺序得到逐位相同的结果；相邻格对共享边的看法一致；
放大只增加不移动不删除。

**契约（`worldgen-contracts`）**：`RoadClass` 按重要性升序声明（派生的 `Ord` 就是重要性）；
横断面表按（等级 × 乡村/城市）索引，**全项目只有一份**（旧代码里有三份互相矛盾的宽度）；
`HeightField`/`WaterField`/`UrbanField` 接口，`PinnedRoads`（规划器给定的路），`RoadTile`/
`RoadNetwork`（id 来自生成方式而不是发现顺序，合并时同 id 内容不同即报接缝错误）。

**路网层（`worldgen-roads`）**：

1. 地面是一张略有扰动的四边形格（2048 m）。四边形的边（**弦**）是相邻格唯一共享的东西，所以弦上的
   一切由弦自己决定。
2. 弦上的**分割点**来自嵌套的一维点过程：每一级（主干 1000 m → 次干 520 → 支路 290 → 小区路 150 →
   巷 78）在“累积密度”坐标里抖动取点，建成区密、乡村疏；粗级是细级的子集，缩小只删点不移点。
3. 一个**面**按级切割：同级的分割点在对边之间配对（不交叉）；没有配对的分割点也拉一条街穿过整个面
   （落在 30 m 槽位上，使相邻格共享节点、不出现几米长的边）。切出的小面交给下一级。叶面是街区。
4. 街只在有镇的地方**建出来**：布局按整个面决定，街在城镇结束处结束。街等级随开发强度降级（村里没有
   主干路）。
5. 弯曲只在最后做：平滑的全局扭曲 + 两端为零的小摆动，所以同一节点的两条路必然在同一点相遇。
6. 坡度超过等级上限的路不修；过水的路，次干及以上建桥，其余不修。
7. **给定道路叠加层**：规划器按地形选线的长路原样保留，生成的街与之相交处切断并共享路口，只是并行
   的街被省略；给定道路在格边界处切开，使每一段只属于一个格。
8. 一个窗口是若干格的网络裁剪到窗口；裁剪点只由线段和边界坐标决定，所以相邻瓦片在边界上重合到位。

测试覆盖：顺序无关、大瓦片 = 其中小瓦片之和（顶点、节点 id、边 id 逐位一致）、缩小只删不改、
无意外交叉、一个镇是一张连通网络、边长/弯曲/街区尺寸分布、等级随城镇度、不同种子不同路、坡度、
桥、给定道路的衔接与规划性。

**接入应用**：`infrastructure::fabric` 把世界数据适配成上述接口（定居点→城镇度场、地形→高程/水系、
路由器的路→给定道路并按等级圆化拐角），城镇的街 = 路网中以定居点为中心的一个窗口，交给
`urban::generate_modern_chinese_city_from_streets` 生成街区、地块、建筑。`generate_infrastructure`
默认使用新规划器（`CityPlanner::Legacy` 保留旧规划器作对照）。区域道路与城镇街道是同一条线，不再有
“交接”问题。河流由地形汇流追踪成折线（带随流量增长的宽度和蜿蜒），城镇的河与桥来自它。

**已知差距 / 下一步**：

- 城市规划仍在世界生成时一次性生成；应改为首次请求时按窗口生成（引擎已具备，需要把引擎持有在宿主里）。
- 区域尺度（地形纹理上的乡村道路格）尚未从路网瓦片绘制；现在只画路由器的路。
- 车道图、路口几何、信号相位（A3b）；与 OpenDRIVE/Lanelet2 互导。
- 建筑仍用旧的地块/建筑生成器，只是改了输入（A4：按街区惰性生成、类型随参数场变化）。
- 乡村与小镇需要自己的形态（沿路带状、院落），目前是缩小的城市网格。
- 路网所有城镇的主轴都沿世界坐标轴；需要随地区变化的朝向场。

## 10. 已实现：树木层（`worldgen-trees` + `src/trees`）

目标：**每一棵树、每一片叶子都不一样**。这不是“多做几个原型再随机挑”，而是每棵树从自己的种子生长。

**生长器（Rust，`crates/worldgen-trees`）**：`grow(spec, lod) -> Tree` 是纯函数，输入是树自己的
`TreeSpec`（物种、种子、高度、开阔度、树龄、季节、健康、枝下高），输出是枝段（两端点 + 两端半径）
和叶片（位置、叶轴、法线、大小、外形/色调参数）。没有全局状态，没有有序随机流：每根枝、每片叶的
种子都由“树种子 + 它在树上的位置”哈希得出，所以同一棵树永远长一样，不同的树没有共用的枝或叶。

- 干：锥度、基部扩张、螺旋/轮生着枝；枝：逐级分叉（受重力与向光性），小枝，叶。
- 树冠包络按树型（圆、卵、伞、垂、塔、层、扇…）由射线步进 `fit` 约束，枝叶不会越过包络。
- 细节层（LOD 0–3）：叶片预算 16000/3500/700/120，木质层级 3/3/2/1；较粗的层用**更大更少**的叶保持
  覆盖率，所以树冠的轮廓和疏密不随距离跳变。
- 季节：叶量、转色（每片叶有自己的“何时变色”）、嫩叶、花期；条件：开阔度/树龄/健康/枝下高。
- 23 个物种（香樟、银杏、梧桐、槐、榆、桂花、雪松、柳、松、水杉、刺槐、榕、桃、杉、合欢、杨、
  苹果、柿、枫、樱、玉兰、桑、枣）。统计测试验证：同种两棵不共用任何一根枝/一片叶，LOD 覆盖率一致，
  叶形参数分布足够宽。

**宿主（WASM，纯 C ABI，无 wasm-bindgen，88 KB）**：`tree_generate(...)` 把树写入一块紧凑二进制缓冲区
（128 字节头 + 枝段 8×f32 + 每叶 位置/长度、轴、法线、外形、色调）。`npm run build:wasm` 生成
`public/worldgen_trees.wasm`；Tauri CSP 增加 `'wasm-unsafe-eval'`。一棵 LOD0 的树约 9 ms。

**渲染（`src/trees`）**：

- **不存网格**。顶点着色器由枝段端点与半径“长出”锥形管；由叶的位置/轴/法线/大小“长出”一片带卷曲和
  中脉折角的叶面。
- 片元着色器按**每片叶自己的参数**裁出轮廓（卵形、掌状、椭圆带齿、针叶束、羽状复叶、扇形、花）、
  画自己的叶脉、按自己的色调/荫蔽/老化/转色时间着色；树皮由沿枝轴拉伸的噪声做出裂纹与板块。没有图集，
  没有重复。
- 每棵树的整体信息（叶色、秋色、花色、树皮色、裂纹、嫩叶、叶形）放在一张共享的浮点表里，一行一棵，
  所以一次绘制可以带上百棵不同的树；阴影与遮蔽（GTAO 的法线通道）用同一套着色器挖出同样的叶片。
- `UniqueForest`：树按 64 m 分块；每块按到相机的距离选 LOD，**按帧预算由近到远**生长，新层级就绪前
  继续显示旧层级（不会出现空洞）。重建一块得到的是同样的树，只是更细或更粗。
- 城市层在语法上与树无关：它只给出“哪里有一棵、什么种、多高”，`plantFromInstances` 把旧的原型实例列表
  换成一片森林；树的种子来自位置，所以同一座城市两次载入长出同样的树。

**已知差距**：高度/开阔度目前来自旧原型的缩放与位置哈希，尚未读取土地覆盖（林内/林缘/孤立木）；
风动画；LOD 之间的过渡仍是整块切换；叶片的半透明/透光是近似；远处（>1.5 km）不画树，应由地表层的
冠层表示接管。
